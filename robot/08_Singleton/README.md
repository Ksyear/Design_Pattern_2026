# 08. Singleton - 비상 정지 래치

> 비상 정지가 둘이면 "내비게이션은 멈췄는데 팔은 계속 움직이는" 상태가 생긴다.
> **그런데 이 패턴을 로봇에 쓰는 것은 위험하다.** 그 위험까지가 이 예제의 내용이다.
>
> 책 예제 : [`../../08_Singleton`](../../08_Singleton) (초콜릿 보일러)

## 1. 어떤 문제를 푸는가

비상 정지는 하드웨어에 **물리적으로 하나뿐인 회로**다. 두 개일 수가 없다.

- "버튼이 눌렸다" 는 사실을 모든 노드가 똑같이 봐야 한다
- 누가 먼저 물어보든 같은 답이 나와야 한다
- 한 번 걸리면 **사람이 풀기 전까지 유지**되어야 한다 (래치)

객체가 둘이 되는 순간 이 셋이 전부 깨진다.
보일러가 둘이면 끓지 않은 우유를 붓고, e-stop 이 둘이면 팔이 계속 움직인다.

## 2. 폴더가 곧 패턴 역할

| 폴더 / 파일 | 패턴 역할 | 하는 일 |
|---|---|---|
| [`estop/EmergencyStopBus.*`](estop/EmergencyStopBus.h) | **Singleton** | 래치 상태 하나를 보관. `instance()` 로만 접근 |
| [`node/NavigationNode.*`](node/NavigationNode.h) | Client | `/cmd_vel` 을 내보내기 전에 래치를 확인 |
| [`node/ArmNode.*`](node/ArmNode.h) | Client | 궤적을 보내기 전에 래치를 확인 |

두 노드는 **서로를 전혀 모른다.** 같은 싱글턴을 볼 뿐이다.

## 3. 적용 방식 - C++ 에서는 한 줄이다

```cpp
// estop/EmergencyStopBus.cpp
EmergencyStopBus& EmergencyStopBus::instance()
{
	static EmergencyStopBus bus;   // 이게 전부다
	return bus;
}
```

**Meyers 싱글턴**이라고 부른다. C++11 부터 함수 지역 `static` 의 초기화는
**스레드 안전이 언어 표준으로 보장**된다.

> 자바의 DCL(이중 검사 잠금), `volatile`, enum 싱글턴 논쟁이
> C++ 에서는 이 한 줄로 전부 사라진다.

### 사본이 생길 구멍을 전부 막았다

```cpp
// estop/EmergencyStopBus.h
EmergencyStopBus(const EmergencyStopBus&) = delete;
EmergencyStopBus& operator=(const EmergencyStopBus&) = delete;
EmergencyStopBus(EmergencyStopBus&&) = delete;
EmergencyStopBus& operator=(EmergencyStopBus&&) = delete;

private:
	EmergencyStopBus() = default;    // 밖에서 만들 수 없다
	~EmergencyStopBus() = default;
```

복사·이동 4종을 지우지 않으면 `EmergencyStopBus bus = EmergencyStopBus::instance();`
한 줄로 **사본이 생긴다.** 그 순간 "하나뿐" 이라는 전제가 조용히 깨진다.

## 4. 실행하면 보이는 것

```
===== 3. 안전 펜스 침입 - 한 곳에서 래치를 건다 =====
  !! E-STOP 래치 : 안전 펜스 라이트커튼 차단
  서로 모르는 두 노드가 동시에 멈춘다 :
    [nav] 정지 유지 (안전 펜스 라이트커튼 차단)
    [arm] 궤적 전송 거부 (안전 펜스 라이트커튼 차단)

===== 4. 사람이 버튼을 풀기 전까지는 계속 막힌다 =====
    [nav] 정지 유지 (안전 펜스 라이트커튼 차단)
```

**한 곳에서 걸었는데 두 노드가 같이 멈췄다.** 둘은 서로를 모른다.
그리고 4번 장면 - 아무도 다시 걸지 않았는데 여전히 막혀 있다.
이것이 **래치**다. "지금 위험한가" 가 아니라 **"위험한 적이 있었는가"** 를 기억한다.

2번 장면은 `instance()` 를 두 번 불러 주소를 비교한다.

```
  instance() 두 번 호출 -> 같은 주소인가 : 예
```

## 5. 이 패턴의 대가 - 로봇에서는 특히 크다

`EmergencyStopBus.h` 주석에 길게 적혀 있는 내용이다. **이 예제에서 가장 중요한 부분이다.**

### (1) 프로세스 경계에서 보장이 끊긴다

```cpp
// main.cpp 끝의 주석
// 이 프로그램을 노드별로 두 프로세스로 나누면 어떻게 될까?
// -> 싱글턴이 프로세스마다 하나씩 생겨서 e-stop 이 한쪽에만 걸린다.
```

싱글턴이 보장하는 것은 **"한 프로세스 안에서 하나"** 다.
ROS 2 는 노드를 프로세스로 나누는 것이 기본이다.
`ros2 launch` 로 nav 노드와 arm 노드를 따로 띄우는 순간 **e-stop 이 두 개가 된다.**

이게 로봇에서 치명적인 이유는 명백하다. **한쪽만 멈춘다.**

### (2) 테스트 격리가 깨진다

앞 테스트에서 건 e-stop 이 다음 테스트에 남는다.
`reset()` 을 공개해 둔 것은 **테스트를 위해 뚫어 놓은 구멍**이다 - 설계상 아름답지 않지만 필요하다.

### (3) 상태 변경은 여전히 스레드 안전하지 않다

`instance()` 의 초기화만 안전하다. `trigger()` / `reset()` 은 아니다.
멀티스레드 실행기를 쓴다면 뮤텍스나 `std::atomic` 이 필요하다.

## 6. 그럼 실제 ROS 2 에서는 어떻게 하나

| 이 예제 | 실제 ROS 2 |
|---|---|
| `EmergencyStopBus::instance()` | **쓰지 않는다** |
| 래치 공유 | `transient_local` QoS 의 latched 토픽 (`/emergency_stop`) |
| 래치 조회 | 서비스 (`/get_estop_state`) |
| 물리적 보장 | 안전 PLC / 하드와이어 회로 - 소프트웨어 바깥 |

분산 시스템에서 "전역 하나" 를 원하면 **전역을 만들 것이 아니라 공유 채널을 만들어야 한다.**

싱글턴이 맞는 답이 되는 경우는 좁다.

- 컴포넌트 컨테이너로 **한 프로세스에 묶는 것이 확정**되어 있고
- 그 상태가 프로세스 밖으로 나갈 일이 없을 때

## 7. 이 예제가 하지 않는 것

- 스레드 안전한 `trigger()` / `reset()` 을 구현하지 않았다 (일부러 남겨 둔 결함)
- 프로세스를 나눴을 때 깨지는 장면을 **실제로 보여 주지는 않는다.** 주석으로만 설명한다
- 래치 상태 변화를 알리는 콜백이 없다. 노드가 **물어봐야만** 안다
  (진짜 시스템은 [`../02_Observer`](../02_Observer) 처럼 밀어 주는 쪽이 맞다)

## 8. 객체지향 관점 - 어떤 원칙을 어떻게 지켰나

**이 패턴은 22개 중 객체지향 원칙을 가장 많이 거스른다.** 그것까지가 학습 내용이다.

| 원칙 | 이 예제에서 |
|---|---|
| **캡슐화** | 유일 인스턴스와 그 접근 방법을 클래스가 직접 관리한다 (지킨 것) |
| **DIP 위반** | 쓰는 쪽이 `EmergencyStopBus` 라는 **구상 클래스 이름을 직접 부른다.** 주입이 아니다 |
| **SRP 위반** | "자기 인스턴스 관리" + "e-stop 상태 관리" 두 책임을 겸한다 |
| **느슨한 결합 위반** | 전역 접근점이라 **의존 관계가 시그니처에 안 드러난다.** 누가 쓰는지 알려면 전수 검색해야 한다 |

**C++ 문법으로 지킨 것**

- Meyers 싱글턴 - 함수 지역 `static` 초기화는 C++11부터 **스레드 안전이 표준 보장**
- 복사·이동 4종 `= delete`, 생성자·소멸자 `private` - 사본이 생길 구멍을 전부 막았다
- `instance()` 가 참조를 반환 - 널일 수 없다

**거스른 것 / 대가**

- **테스트 격리가 깨진다.** `reset()` 은 그 때문에 뚫어 둔 구멍이다
- 프로세스를 나누면 "하나" 라는 보장이 끊긴다
- 상태 변경(`trigger`/`reset`)은 여전히 스레드 안전하지 않다

> 대안을 먼저 생각할 것 : 의존성 주입(생성자로 넘기기), latched 토픽, 서비스.
> 싱글턴은 **"한 프로세스 안" 이 확정일 때만** 맞는 답이다.

## 9. 실행

### 이 폴더만 단독으로

```sh
cd robot/08_Singleton
make          # build/08_Singleton 에 실행 파일 생성
make run      # 빌드하고 바로 실행
make clean    # build/ 삭제
```

### 저장소 루트에서 (다른 패턴과 함께)

```sh
make robot                    # 로봇 예제 22개 전부 빌드 -> build/bin/robot_*
make run-robot-08_Singleton    # 이 예제만 빌드하고 실행
make run-robot-all            # 22개를 순서대로 실행
```

두 경로의 빌드 옵션은 같다 - `-std=c++20 -Wall -Wextra -Wpedantic -O1`, **경고 0개**를 유지한다.
산출물 위치만 다르다 - 단독은 `08_Singleton/build/`, 루트는 `build/bin/`.

## 10. 확인 질문

> 이 프로그램을 `nav` 프로세스와 `arm` 프로세스로 나누면 3번 장면은 어떻게 되는가?

`nav` 만 멈추고 **팔은 계속 움직인다.**
